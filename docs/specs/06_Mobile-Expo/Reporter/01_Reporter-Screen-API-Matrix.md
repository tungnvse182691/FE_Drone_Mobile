# Reporter screen/API matrix

All screens below are `PROPOSED_EXPO_UI`; linked routes and actor guards are `CURRENT_IMPLEMENTED_BE`. `B` means Android bearer access token, `K` means `Idempotency-Key`, and `V` means strong quoted `If-Match` from the latest response. Exact schemas remain in the [Phase 2C catalog](../../04_API-Contracts/02_Full-API-Catalog.md).

| ID / screen / actor | Navigation and prerequisite | Initial reads | Commands / exact APIs | DTO and key fields | States, privacy and status |
|---|---|---|---|---|---|
| RPT-01 Registration | Public entry; no token | none | API-010 `POST /api/v1/auth/reporter-registrations` + K | `RegisterReporterRequestDto`; email, password, displayName, reporterType | 202 intent; validation/429/503; never log or persist password. `CURRENT_IMPLEMENTED_BE`, `NOT_VERIFIED_EXPO_E2E` |
| RPT-02 OTP verification | From RPT-01 intent | none | API-012 `POST /api/v1/auth/reporter-registrations/verify` + K; API-011 `POST /api/v1/auth/reporter-registrations/resend` + K | intentId, otp; resendAfterSeconds/status | expiry, attempts and cooldown are server authority; return to login after success. |
| RPT-03 Android login/session | Public login; token required after success | none; login response supplies initial identity | API-002 `POST /api/v1/auth/android/login`; API-003 `POST /api/v1/auth/android/refresh`; API-007 `POST /api/v1/auth/logout` + K | `LoginRequestDto`, `RefreshRequestDto`, `AuthTokenResponseDto`; access/refresh/tokenType/expiresIn/user | single-flight refresh, atomic token replacement, 401 relogin; SecureStore boundary. |
| RPT-04 Account/password | Authenticated Reporter | none; identity from login/session response | API-004 `POST /api/v1/auth/change-password` + K; API-005 `POST /api/v1/auth/forced-password-change` where server says required; API-008 public recovery request | password DTOs from catalog | `mustChangePassword` blocks business commands; recovery is request-only, not self-reset. |
| RPT-05 Private photo capture/pick | Authenticated; camera/library/location permission | API-212 session recovery; API-208 metadata | API-211 create upload + K; API-214 part URLs + K; raw storage PUT; API-213 complete + K + V | create/part/complete/upload/file metadata DTOs; checksum, mediaType, size, ETag/version | permission denied, URI unavailable, expiry, resumable retry; private owner only. |
| RPT-06 Verification queue | Authenticated; after upload complete | API-212 `GET /api/v1/reporter-evidence/uploads/{uploadId}`; API-208 `GET /api/v1/reporter-evidence/files/{fileId}` | no command | upload/file status, checksum, version | poll boundedly while foreground; `complete` is not `VERIFIED`; failed/expired is recoverable by a new upload. |
| RPT-07 Create report | Authenticated; at least one own VERIFIED file | optional API-208 metadata | API-216 `POST /api/v1/reports` + K | `CreateReporterReportRequestDto`; description, evidence[fileId,fileVersion,locationSource,capturedAt,location] | 201 + Location/ETag; unknown response replay same K/payload; no projectId/defectId. |
| RPT-08 My reports | Authenticated Reporter | API-215 `GET /api/v1/reports` (query `pageSize`, `cursor`) | none; refresh/load-more repeats the read | `OwnReportPageDto`; items,nextCursor | empty/partial/retry; cursor/cache partitioned by account. |
| RPT-09 Report detail/evidence | Authenticated owner | API-217 `GET /api/v1/reports/{reportId}`; API-218 private download; API-210 publication download when IDs are published | none | `OwnReportDto`; version/ETag, evidence, routingStatus, publicUpdates, supplements | 403/404 never reveal another owner's report; do not infer Defect/repair from routingStatus. |
| RPT-10 Supplement and updates | Authenticated owner; latest detail V; new VERIFIED evidence | API-217 detail; API-215 refresh; API-210 published evidence | API-219 `POST /api/v1/reports/{reportId}/supplements` + K + V; use RPT-05 upload commands for new evidence | supplement request DTO; reportId, description, evidence, version | 412 reload and show conflict; publications are read-only server output. |

**Authorization:** API-010/011/012/002/003/005/008 are anonymous credential/bootstrap routes. API-007 and API-208–219 use bearer/Reporter resource guards. Reporter does not call Case, Candidate, Defect, Survey, FIELD, Crew offline or project administration routes. Backend remains authoritative for validation, ownership, publication recipients, `VERIFIED`, status and version.

**Source evidence:** `AuthController`, `ReporterRegistrationsController`, `ReporterEvidenceController`, `ReportsController`, `AuthService`, `ReporterEvidenceService`, `ReporterLifecycleRepository`, and DTOs are linked by each API entry in the catalog. Exact source SHA is the Phase 2C baseline; browser/mobile runtime is not supplied.
